# Recall Relay: use your model, keep the memory

Recall Relay is a bring-your-own-key integration pattern. It checks a user-owned Recall archive before a provider call; on a safe hit it returns the existing asset, and on a miss it calls the provider from the user's device/process and captures the completed bytes back into Recall.

Provider credentials are never sent to Recall or written to B2. For a hosted relay endpoint, use a scoped Recall integration key; for the strongest privacy model, self-host Recall against your own B2 bucket.


## Private workspace setup

Create a workspace once with an existing scoped Recall integration key:

```bash
curl -X POST https://your-recall.example/api/v1/workspaces \
  -H "X-Recall-Key: your-integration-key" -H "Content-Type: application/json" \
  -d '{"label":"My private creative vault"}'
```

Save the returned `workspace_id` and one-time `workspace_key` in your password manager. Pass both to `RecallRelay`; every asset, prompt, receipt, feedback record, and search then lives under its isolated B2 prefix. Do not place them in frontend code.

## What prompt matching does today

1. **Exact:** normalized prompt equality is always a 1.0 exact match.
2. **Text:** token Jaccard score plus tag overlap catches close wording.
3. **Semantic:** optional Gemini embeddings score paraphrases with cosine similarity. The live threshold for an automatic *recommendation* is 0.70.
4. **Intent Firewall:** even a high semantic score is rejected when brand, campaign, format, license, or language conflicts; missing required profile fields also block reuse.
5. **Human choice:** no result is served automatically. The caller must retrieve, fork, or deliberately generate.

Every assessment produces a Recall Ledger receipt. The raw prompt is retained only in the user's generation record; the receipt contains a salted HMAC commitment instead of repeating it.

## Media matching

Recall stores SHA-256 for every output. `POST /api/v1/capture` deduplicates an externally generated asset when its exact bytes are already archived, avoiding an additional B2 copy. Image captures also compute a 64-bit difference hash for future resized/compressed near-duplicate lookup. Exact output matching saves storage; prompt/semantic matching before provider invocation is what saves model cost.

## Install the relay

```bash
pip install recall-relay
recall-relay doctor
```

The package is published to PyPI through GitHub Trusted Publishing; no long-lived PyPI token is used.

## Gemini quickstart

```python
from recall_relay import RecallRelay
relay = RecallRelay("https://your-recall.example", gemini_key="your Gemini key", workspace_id="ws-...", workspace_key="save-this-once")
result = relay.generate_gemini(
    "Editorial cobalt glass product image on warm paper",
    tags=["launch", "cobalt"],
    intent={"brand":"Recall", "format":"1:1", "license":"campaign-internal"},
)
print(result.status, result.generation.get("asset_url"))
```

Install from PyPI and import `RecallRelay`. On `reused`, no provider request occurred. On `generated_and_captured`, `result.media` holds the new bytes and Recall has archived them for future checks.

## Capture an existing result

For media generated by another workflow, send its base64 bytes to `POST /api/v1/capture` with a private workspace pair or `X-Recall-Key`; arbitrary public uploads are rejected. Recall records this as `external_capture`, not a Genblaze-generated manifest. Set `cost_usd` when you know the effective provider cost. Recall labels it `caller_reported`, uses it for future avoided-cost accounting, and leaves it unpriced when omitted. The resulting byte hash remains verifiable; Genblaze verification continues to apply only to runs Recall orchestrated through Genblaze.

## OpenAI Relay

Set `OPENAI_API_KEY` locally, then use:

```bash
recall-relay openai "Editorial cobalt glass product image" --model gpt-image-1 --output hero.png --cost-usd 0.067
```

The client calls `POST /v1/images/generations` only after Recall returns a safe miss, asks for base64 image data, and captures those bytes in the private workspace. The OpenAI key is never sent to Recall.

## Any provider relay

`RecallRelay.generate_with()` is the provider-neutral integration point. It accepts a local callback that returns completed media bytes. Recall runs the reuse and policy check first. A safe hit performs the explicit free retrieval and records avoided cost; only a safe miss invokes the callback, then the bytes are captured with the provider/model details. This lets an application add Recall in front of any image, video, or audio provider without proxying its provider credential through Recall.

```python
result = relay.generate_with(
    "Cobalt launch asset",
    generator=lambda prompt: call_your_provider(prompt),
    provider="your-provider", model="your-model", media_type="image/png",
    tags=["launch"], intent={"brand":"Acme", "format":"1:1"},
    cost_usd=0.42,
)
```
## Trust and limits

- `cost_usd` is supplied by the caller and stored as `caller_reported`; Recall never invents external-provider pricing.
- A private workspace pair or scoped `RECALL_API_KEY` is required to capture media.
- Provider secrets remain in the caller process and are never included in Relay errors. Recall workspace headers are origin-scoped and are never attached to Gemini, OpenAI, or custom-provider requests.
- Capture MIME types are allowlisted and checked against the actual file signature before B2 storage.
- Each capture is limited to 18 MB by default (`RECALL_MAX_CAPTURE_BYTES` server-side and `max_media_bytes` in the client). Larger video/audio workflows should use a future signed multipart path rather than base64.
- `RecallRelayError` exposes a safe HTTP status and response detail for operational handling.
