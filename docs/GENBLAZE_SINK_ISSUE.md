# Genblaze ObjectStorageSink follow-up

## Current status - 2026-07-25

The current package set (`genblaze 0.4.4`, `genblaze-core 0.3.7`, `genblaze-s3 0.3.6`) successfully uploaded a local `Asset` to the live Recall B2 bucket through `ObjectStorageSink.put_asset(...)`. This confirms the direct sink/backend credential path is valid.

A subsequent end-to-end provider pipeline attempt with `RECALL_NATIVE_SINK=true` completed without returning an output asset to Recall, so the feature flag has been returned to `false`. The proven direct-B2 archival path remains live and preserves both the generated bytes and the canonical Genblaze manifest.

This is intentionally documented as a remaining adapter/pipeline integration issue rather than claimed as native end-to-end success. The no-provider reproduction lives in `scripts/native_sink_diagnostic.py`; the provider-pipeline failure is a useful concise follow-up for Genblaze maintainers.
